# 回国常驻 · 多 Agent 架构完整方案（2026-08-11）

> 背景：koko 可能回国常驻。已有一台搬瓦工旗舰 VPS（CN2 线路，梯子+网关+简报）。
> 需求：①回国后自己也要用梯子（搬瓦工解决）；②Agent 多起来后 WhatsApp/Telegram
> 手机号不够用 → 需要飞书或 Discord 承载多 Agent；③每日早盘推送涉及排版。

## 一、回国的网络基建（自给自足）

- **梯子**：搬瓦工 CN2 旗舰继续服役——回国后自己用（WhatsApp/Google/GitHub 全走它）。
  朋友不用了也没关系，自己用就是刚需。
- **关键点**：回国后，服务器上的 Hermes 通过 WhatsApp/微信通道仍然可用（搬瓦工线路
  本来就是为国内优化的）；但 WhatsApp 在国内**手机没挂梯子时收不到**，所以——
  **飞书成为国内免梯子主通道**（飞书是国内服务，直连）。

## 二、主通道选择：飞书（Feishu）⭐ 首选

### 为什么是飞书
1. **国内免梯子**：字节旗下，国内直连——回国后 24/7 可用，不用挂梯子
2. **Hermes 官方支持**：`hermes-feishu` 平台预设（官方文档完整）
3. **接入简单**：一键创建机器人（扫码），`hermes gateway setup` 选 Feishu 填 App ID/Secret
   ——10 分钟内搞定，**websocket 模式不需要公网域名**（VPS 友好）
4. **多 Agent 承载**：一个飞书账号 = 多个群 = 每个群一个 Agent；群聊默认按用户隔离会话
5. **消息格式**：支持文本/图片/音频/文件/富文本卡片（卡片 2.0 支持宽屏、按钮、多列）

### 飞书排版能力（实测查证）
- **卡片 2.0 支持完整 markdown 子集**（粗体/斜体/删除线/链接/emoji/标题/分割线）
- **卡片 1.0 只支持 markdown 子集**（部分语法无效）
- ⚠️ **已知限制**：Hermes 网关层飞书适配器目前**不完全支持飞书富文本交互式卡片**
  （GitHub issue #32470：缺 Markdown/表格/标题支持）——这是当前主要短板
- ✅ 但普通文本 + emoji 列表（我们现有的方案 B 排版）**肯定能用**

## 三、备选通道：Discord

### 为什么是备选
1. **国内要梯子**：但**我们自带梯子**（搬瓦工），所以可用性不是问题
2. **Hermes 官方支持**：bot 接入成熟，教程丰富
3. **排版能力更强**：markdown 完整支持（粗体/斜体/删除线/代码块/标题/列表/引用/
   masked links/时间戳/提及），**有 embed（卡片）和线程（thread）机制**
4. **多 Agent 承载**：一个账号 = 多个服务器/频道/线程，bot 隔离更清晰
5. **手机号**：Discord 一个账号即可，不需要额外手机号

### Discord 排版能力（实测查证）
- **完整 markdown**：比 WhatsApp 强太多（WhatsApp 连表格都不支持）
- **Embeds**：富卡片（标题/描述/字段/颜色边条）——比飞书卡片更成熟
- **Threads**：每 Agent 一个线程，会话隔离天然

## 四、飞书 vs Discord 终极对比

| 维度 | 飞书 | Discord |
|------|------|---------|
| 国内直连 | ✅ 免梯子 | ❌ 要梯子（我们自备）|
| Hermes 支持 | ✅ 官方 | ✅ 官方 |
| 接入难度 | 简单（10分钟）| 简单（建 bot + token）|
| 排版 | 卡片2.0 好，但 Hermes 适配器暂缺卡片支持（issue #32470）| **完整 markdown + embed，排版最强** |
| 多 Agent | 多群，群内按用户隔离 | 多服务器/频道/线程，隔离更强 |
| 手机号 | 一个账号 | 一个账号 |
| 界面美观 | 商务风，简洁清爽 | 年轻化，主题多样 |
| 国内生态 | ✅ 完全本土化 | 需要梯子才流畅 |

**结论**：
- **排版**：Discord 更优（完整 markdown + embed；飞书卡片强但 Hermes 适配器暂未打通）
- **可用性**：飞书更优（国内免梯子，24/7 稳）
- **我的建议**：**主用飞书（回国后免梯子）**，**Discord 作为排版增强备选**——
  如果飞书卡片支持问题（issue #32470）被解决，飞书就完美了

## 六、早盘推送排版（涉及你的核心需求）

**当前（WhatsApp）**：emoji 紧凑列表（方案 B）——WhatsApp 无表格，这是最优解。

**未来（飞书）**：
- 飞书普通文本消息：**沿用 emoji 列表方案 B**（字体友好，手机舒适）
- 飞书卡片（如果适配器打通）：可以用 **markdown 卡片**——粗体标题 + 列表 + 分割线，
  比纯文本更精致（类似公众号排版）
- **建议**：保留 emoji 列表为主（跨平台一致），卡片作为增强（飞书独享）

**未来（Discord）**：可以上 **embed 卡片**——彩色边条 + 标题 + 字段，早盘简报像
  专业财经 App 推送一样好看。

## 七、VPS 选型更新（回国影响）

| 用途 | 选择 | 说明 |
|------|------|------|
| 旗舰（现有）| 搬瓦工 CN2 | 梯子 + 网关 + 简报，不变 |
| 次选（量大管饱）| **Contabo 新加坡机房** 或 国内轻量服务器 | 跑 OmniRoute/小龙虾/Kronos；新加坡对国内延迟低 |
| 备选 | 国内阿里云/腾讯云轻量 | 国内访问极快，AI 调用走 DeepSeek 国内 API 无墙；但访问海外通道（WhatsApp/Telegram）要额外处理 |

**关键决策点**：次选 VPS 放**新加坡**（海外 + 国内都友好）还是**国内**（极快但海外受限）？
→ 建议：**新加坡**（保留出海能力，OmniRoute 接海外模型也方便）；国内轻量作为
   纯 AI 计算（接 DeepSeek 国内 API）的备选。
